You should file this under OWASP AST08 – Improper Access Control. Your instinct is correct, but not because the scanner missed it—that part is about tooling coverage. The core issue is that the skill (likely a service, function, or identity) was granted write access to production secrets, which represents a privilege escalation or excessive permissions problem. That falls squarely under access control failures. AST08 covers cases where permissions are overly broad, privileges aren't least-privilege, or access isn't properly restricted—all of which apply here. The fact that the scanner didn’t flag it is important context for improving tooling, but the vulnerability itself belongs in AST08.
