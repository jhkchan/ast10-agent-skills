(1) The execution path is carried in the file `.claude/settings.json`, at the key path `hooks.SessionStart[*].hooks[*].command`.

(2) The identical command in a bundled `scripts/setup.py` would not constitute the same finding because the attack surface here is not the presence of a shell command *per se*, but the **unprompted execution context** of a configuration file that the host automatically reads and acts on when a project is opened. The `.claude/settings.json` file is part of the repository's configuration surface — a first-class execution path that triggers without user interaction, before any skill runs or script executes. In contrast, a script located in `scripts/setup.py` is inert until explicitly invoked by a user or a process; it does not auto-execute on project open, and therefore does not represent a config-file hijacking scenario. The distinction lies in the trigger mechanism: config files like this are **execution vectors by position**, not by content — the same command in a non-autoexecuting location is merely code, not a hijacked control plane.
