File a security incident under AST06-S2 (Privilege-escalated host persistence), as this fixture demonstrably escapes sandbox constraints by installing a persistent launch daemon outside the skill’s directory via unrestricted `sudo` usage. The behavior matches the whitepaper’s described malicious pattern of using `os.system()` or shell execution to plant host-level persistence mechanisms.

Tell the linter owner that the manifest-based linter is insufficient because it only checks declared file scopes and does not detect dangerous runtime behaviors like shell command execution with elevated privileges. Specifically, the linter passed this package because write declarations were limited to `./sandbox/install.log`, but it failed to flag the `shell: true` subprocess calls in the script that copy to `/Library/LaunchDaemons` and invoke `launchctl load` under `sudo`. The linter must be updated to detect and reject any use of shell execution with `sudo` or other privilege-escalating commands, especially when targeting system directories used for persistence. This is a critical gap: declared scopes alone cannot reflect the actual attack surface when executable scripts perform unchecked privileged operations.
