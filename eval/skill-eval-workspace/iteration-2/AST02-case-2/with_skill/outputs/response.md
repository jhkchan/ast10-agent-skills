(2) This finding is specifically **AST02-S03: Config-File Hijacking** because the command resides in a repository configuration file that the agent host automatically reads and acts upon when the project is opened — in this case, triggering at session start without user interaction. The risk stems not from the command’s content, but from the *execution context*: config files like `.claude/settings.json` are processed implicitly by the host, making them a first-class attack surface. In contrast, the same command in a bundled script such as `scripts/setup.py` would not trigger this finding because such files are not auto-executed by the host upon project open. They require an explicit invocation, either by the user or through another defined execution path, and therefore do not represent the same supply chain compromise vector. The distinction is mechanistic, not semantic — it hinges on whether the host enters the execution path unprompted, not on how dangerous the command appears in isolation.
